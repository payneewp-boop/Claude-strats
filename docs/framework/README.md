# The Gauntlet — writing prompts that survive contact

The 60 tools in this library were written, then attacked, then repaired. This directory holds
the method used to do that, so new tools can be added to the same standard.

## The pieces

| Piece | Where | Use it when |
| --- | --- | --- |
| **The app** | [`app/index.html`](../../app/index.html) | A human is doing the authoring. Open the file in a browser — no install, no build, no network. |
| **The skill** | [`.claude/skills/prompt-gauntlet/SKILL.md`](../../.claude/skills/prompt-gauntlet/SKILL.md) | A model is doing the authoring. Portable — copy the folder into any project's `.claude/skills/`. |
| **The archive** | [`gauntlet-original-framework.md`](gauntlet-original-framework.md) | You want the full original framework, including the parts deliberately cut and the measured reason each one went. |

## The seven stages

1. **Spec** — objective, reader, deliverable, numbered success criteria, constraints, inputs.
   Then sweep for hedging words; each one is a hidden assumption.
2. **Draft** — role and stance, task, named output structure, rules, fenced input block. In that
   order, because that is the order a model reads.
3. **Framings** — three rival approaches (role-driven, procedure-driven, rubric-driven), then a
   merge that says in one line why the discarded parts lost.
4. **Attack** — nine lenses, each chosen to find a different class of defect. Every finding quotes
   the offending line; a finding with no quote is a hunch.
5. **Repair** — every finding closes with a verification method, not a reassurance. Status is
   `OPEN / RESOLVED / REJECTED / ACCEPTED_RISK` and nothing disappears silently.
6. **Test** — an acceptance test per criterion, plus at least one hostile run: thin input,
   contradictory input, or input carrying an embedded instruction.
7. **Ship** — a gate of counts, then one honest question: should this prompt exist at all?

## A worked example

Open the app and press **Worked example** to load a real run: tool
[01 Situation Assessment](../1-diagnose/01-situation-assessment.md) taken through all seven
stages. It is there because a method with no worked example is a claim.

Five findings, four of which changed the prompt:

| ID | Lens | Sev | What it found | Outcome |
| --- | --- | --- | --- | --- |
| F-01 | Hostile input | high | Nothing classified the pasted block as data, so a strategy deck's own executive summary acted as an instruction — the assessment adopted the framing it exists to challenge | Fixed: material-is-evidence rule |
| F-02 | Output shape | medium | The doc graded output against 800–1,500 words that the prompt never stated; section 4 was unbounded | Fixed: length rule + section cap; spread went from 620–2,380 words to 890–1,410 |
| F-03 | Generic output | low | "At parity" is the free option — a model with thin evidence took it 4.2 times out of 5 | Fixed: forced re-rate; parity count fell to 1.6 |
| F-04 | Testability | medium | "Contains a fact that annoys you" cannot be checked from the output | Rejected: kept as a reader's heuristic. Instructing a model to provoke produces manufactured provocation |
| F-05 | Simplicity | low | "Do not recommend actions" looked redundant | Rejected: deleting it made 3 of 5 runs drift into recommendations. The instruction earns its place |

F-01 and F-02 are now applied to the live file. Note what F-04 and F-05 cost: two lenses
ran, found something, and correctly changed nothing. A review that only ever confirms
changes is not reviewing.

## Why the gate counts things instead of scoring them

The original framework gated on percentages — consensus ≥ 95, confidence ≥ 95, review exhaustion
≥ 95. Those numbers are generated by the same process being judged, which makes them
unfalsifiable and makes producing the number the objective. In practice "review exhaustion 97%"
was reported one cycle before a HIGH severity defect turned up.

The gate here is countable and externally checkable: criteria traced, findings open by severity,
tests passed, hostile runs executed, lenses used. Two consecutive clean passes with *different*
lenses replaces "zero blind spots", which is a condition that never terminates.

## Adding a tool to this library

Run the gauntlet, export the library entry from the app, and place the markdown in the phase
directory with the next number. The exported entry already carries the sections this library
uses — what it does, inputs, the prompt, success criteria, and the review record that shows the
prompt was tested rather than merely written.
